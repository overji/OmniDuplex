# Eight-GPU ordinary-CE SFT → split benchmark

This replaces the failed GRPO pilot and its four-GPU follow-up. Existing benchmark predictions are preserved; their workers are paused so all eight GPUs can train. No GRPO restart is queued.

## Training

- Start from the original external MiniCPM-o-4.5 base, not an SFT/GRPO checkpoint.
- `decision_loss_mode=plain_ce`: uniform CE over supervised output tokens within each QA, then the existing equal-QA batch reduction. No category/event balancing.
- GPU 0–7, one QA per GPU per microbatch, gradient accumulation **2**: effective batch remains **16**. The earlier four-GPU setting used accumulation 4.
- Same prepared 3996/1004 train/validation QA split by video, learning rate 1e-6, two epochs, full-video silence/all-response supervision, 65536-token cap, ZeRO-2 CPU optimizer. Data-dependent invalid trajectories remain explicitly excluded as before.
- Expected 500 optimizer updates. Save every 50 updates, retain one numbered checkpoint plus final.
- TensorBoard enabled; W&B disabled. More GPUs can reduce time per update, but shared CPU offload, memory bandwidth and the longest video in a microbatch can limit scaling.

Operational config: `train/outputs/plain_ce_dp8_20261101/chain.json`; training config `sft.json`; current state `status.json`; logs `training.log` and `controller.log` in the same directory.

## Automatic evaluation

`train/scripts/sft_then_split_bench.py` requires final reports and checkpoint shards from all eight ranks, verifies 500 updates and the exported model identity, then launches the existing benchmark implementations on disjoint GPU pools:

| GPUs | Work | Output |
| --- | --- | --- |
| 0–3 | AOI-Bench realtime, latest plain-CE checkpoint | `benchmark/results/minicpmo_plain_ce_dp8_aoi_20261101` |
| 4–7 | OmniPro under the existing AOI ±3-second timing protocol, followed by four-replica content Judge | `benchmark/results/minicpmo_plain_ce_dp8_omnipro_20261101` |

OmniPro keeps the prior frozen sample order and inclusive one-to-one timing windows. Both benchmarks keep the reply plus ordinary-text `<|task_start|>` instruction protocol. No probe evaluation is added.

Paired live comparisons against existing baseline predictions refresh in `benchmark/results/plain_ce_live.md` once benchmarks begin. A failure during training/export blocks inference rather than evaluating incomplete weights. Old benchmark queues remain paused; this chain does not revive them or GRPO.
