# 多轮Agent训练调研与OmniDuplex的对应关系

日期：2026-10-31。目的：核对“多轮任务是否必须RL、SFT是否只能学习格式”。
本次为针对性文献调研，不是穷尽性系统综述；选取轨迹SFT、纠错自训练、流式交互和多轮RL的代表工作。
所有外部证据来自作者论文、官方报告或官方项目页面。未据此调整当前实验。

## 结论

不能把当前RTD退化归结为“SFT天生训不了多轮”。轨迹SFT可以学习多步行为；
更有证据支持的局限是：静态成功示范对模型自身错误历史的覆盖不足，token CE与自由生成的轨迹目标不一致。
RL可直接优化模型生成的轨迹，但整段单一优势、长时序稀疏反馈和奖励失真也会造成失败。

## 代表证据

| 工作 | 实际训练路径 | 可迁移启示与限制 |
|---|---|---|
| AgentTuning | 1866条过滤后的交互轨迹，混合通用指令做SFT；不是“必须RL”的实例 | 完整交互轨迹与混合训练可以提升Agent能力；它的实验也发现只训练Agent数据会损伤泛化。任务与流式监控不同。 |
| Agent-R | 用MCTS获得好/坏分支，构造从错误前缀转向正确行为的修订轨迹，迭代SFT | 补“如何从错误恢复”可以继续使用监督学习。不能原样拼接工具环境轨迹到物理视频：视频时间不可以倒退。 |
| JoyAI-VL-Interaction | 时间对齐交互SFT混合普通对话，角色加权CE；之后接GRPO及内容Judge | RL针对开口、等待和委托；使用以答案为中心的窗口采样缩短轨迹，并非证明几百秒整轨迹GRPO已经稳定。它是视觉优先模型。 |
| Gander | 官方项目给出Thinker/Talker分阶段训练；报告称长时序OPD/RL尚未充分优化 | 多轮能力不是“用了RL”的同义词；大规模交互、任务生命周期、等待与负监督也重要。不能将“尚未充分优化”写成绝对未使用RL。 |
| RAGEN | 多轮环境rollout、轨迹级优化，分析Echo Trap等退化 | RL也可能循环、奖励方差坍塌；v1附录C在Sokoban/FrozenLake的特定设置中，SFT为74.6%/23%，所比较StarPO-S为20.3%/21.8%。不是跨任务、跨算力的普适排名。 |
| GiGPO | 将整轨迹相对优势与相同锚点状态的局部优势结合 | 直接针对单一轨迹优势无法定位错误步骤的问题；相同视频秒不等于相同状态，模型历史也属于状态，不能直接按时间戳套用锚点分组。 |

## 他们的“多轮训练”具体多在哪里

轨迹不是简单把若干个独立问答拼长，而是动作、环境观察和更新后的历史构成连续状态。
SFT学习在示范状态下采取下一动作；多轮RL则让模型行动、获取后续观察，再评价实际走出的轨迹。
Agent-R一类方法处在二者之间：更新仍为SFT，但训练状态来自模型自身的探索与错误。
因此应分别讨论数据来源、状态覆盖、优化目标，而不是只讨论SFT/RL的名称。

对视频任务，外部画面通常不因模型说话而改变，但模型输出历史会改变其后续决策。
所以它与工具Agent并不完全相同；可迁移的是自生成历史训练、恢复能力、信用分配和状态管理思路。

## 当前实现的真实位置

- 当前SFT已按完整QA监督全部reference responses，不是逐条单回复训练。
- event-balanced loss与完整视频尾段改善了监督预算和覆盖；依然采用参考历史。
- 已实现confusion_judge奖励，显式计入TP质量、FP、FN及归一化TN。
- 但当前GRPO仍将这些分项聚合为一个轨迹标量，组内标准化后用于整条轨迹的动作token。
  “奖励里有逐事件计数”不等于“每个动作已有独立优势”。
- 没有实际验证当前RL能修复数百秒循环；也不能用训练CE降低替代自由生成评估。

## 建议的后续实验（设计建议，尚未执行）

1. 保留当前完整视频SFT作为可审计基线，以协议、内容及基础开口能力作为warm start。
2. 建立少量人工/音视频核验的状态变化、累计/去重计数训练集，明确事件穷尽性；仅参考文本Judge不足以确认漏标。
3. 构造本模型的纠错前缀：重复回应、提前计数、已经漏答等；纠正目标必须符合当前真实时间和证据。
   错误前缀只作为上下文，不对其错误输出做正向CE；后续正确动作和等待才计算监督。
   不能把一个人造反思提示视为部署时必然存在的信号，也不能把视频状态倒回去接另一个好分支。
4. 先在较短、包含至少两次触发和中间/末尾等待的片段上试多轮RL，之后再延长并测完整视频。
   更早视频证据仍需保留/因果预填，不能只剪掉前缀却要求模型记得累计数量。
5. 对比轨迹级GRPO与更细的局部/分段信用分配。分段必须包含必要历史，跨段计数和去重状态不能重置。
6. 等价预算下比较：当前SFT、SFT+纠错、SFT+GRPO、SFT+纠错+GRPO。
   固定验证QA与解码设置，报告首次/后续召回、FP密度、最坏轨迹、内容/调用正确性及长短视频分组。

这些是基于文献与本地现象的研究建议，不是上述论文已经在AOI/OmniPro证明的结论。
