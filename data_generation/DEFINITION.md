# 实时音视频主动触发任务分类
本文将原有八个任务按触发逻辑归为四类，并为每类增加一个触发后执行的 Agent 任务，共十二个任务。括号中的原任务编号用于与原文对照。每个 Agent 任务都允许用户指定工具调用、复杂推理，或同时指定两者。
| 大类 | 包含任务 | 核心输出 |
| --- | --- | --- |
| 1. 事件触发 | 实时事件提醒（原 Task 1）、事件驱动实时描述（原 Task 5）、事件发生后处理相关事务（Agent） | 事件出现时提醒、描述事件，或执行相关事务 |
| 2. 条件触发 | 语义条件提醒（原 Task 4）、情境满足后准备信息或提出建议（Agent） | 条件满足时提醒，或执行相关事务 |
| 3. 计数触发 | 实时事件计数（原 Task 7）、条件计数提醒（原 Task 3）、独立对象计数（原 Task 8）、数量达到阈值后整理或调整计划（Agent） | 报告数量，或在数量达到阈值后执行相关事务 |
| 4. 目标触发 | 目标定位提醒（原 Task 2）、离散状态变化监测（原 Task 6）、指定目标出现后完成相关任务（Agent） | 报告目标位置和状态，或在目标出现后执行相关事务 |
## 1. 事件触发
### 1.1 实时事件提醒（原 Task 1）
**任务描述**  用户预先指定一个需要关注的事件。模型持续监听音视频流，并在事件首次发生或再次发生时主动提醒用户。
**典型指令**
- “听到门铃声时提醒我。”
- “看到有人摔倒时提醒我。”
- “当有人叫我的名字时告诉我。”
- “看到仪表盘温度变红时提醒我。”
**任务场景**  家庭安全监控、车载驾驶辅助、智能眼镜、工厂和设备监控、老人或儿童看护、线上会议中的关键词提醒。
**输入**
- 连续视频流和/或连续音频流；
- 用户在任务开始时提供的事件描述；
- 可选的事件类别、置信度或提醒方式。
**期望输出**
- 是否触发提醒；
- 触发时间；
- 事件类型；
- 简短自然语言提醒。
**任务约束**
1. 只能使用触发时刻之前已经观察到的信息。
2. 事件发生后应在规定时间窗口内响应。
3. 不应因相似但不满足条件的事件频繁误触发。
4. 同一事件持续存在时，默认只提醒一次，除非用户要求重复提醒。
5. 如果触发信号来自音频、视频或二者结合，需要正确识别触发模态。
6. 事件不发生时必须保持沉默。
### 1.2 事件驱动实时描述（原 Task 5）
**任务描述**  用户要求模型持续关注某类事件，并在事件发生或场景发生显著变化时，主动描述发生了什么。
**典型指令**
- “帮我实时描述球场上发生的重要事件。”
- “看到设备状态变化时告诉我发生了什么。”
- “有人进入房间时，描述一下现场发生的变化。”
- “当画面中出现异常动作时解释一下。”
**任务场景**  体育赛事解说、直播辅助、现场作业、安防监控、无障碍辅助、智能眼镜环境解说。
**输入**
- 连续音视频流；
- 用户指定的关注对象或事件类型；
- 可选的描述风格、详细程度和语言。
**期望输出**
- 事件发生时间；
- 事件内容；
- 相关人物、物体及其关系；
- 必要的前后变化和语义解释。
**任务约束**
1. 只描述当前或已发生的事件，不预测未发生的事实。
2. 描述必须与时间窗口对齐。
3. 应过滤重复、琐碎或无关事件。
4. 需要区分事实描述和推测性解释。
5. 用户说话时不能随意抢话，除非事件重要或用户明确要求主动播报。
6. 连续描述应保持上下文一致，避免前后矛盾。
### 1.3 事件发生后处理相关事务（Agent 任务）
**任务描述**  用户指定一个事件，以及事件发生后希望 Agent 完成的日常事务或需要考虑的问题。事件由音频、视频或二者共同触发；触发后，Agent 可调用日常应用工具、进行复杂推理，或两者兼做。
**典型指令**
- “会议上有人给我安排任务时，帮我记到待办里，并考虑什么时候做。”
- “快递送到门口时，帮我核对是哪件包裹，并考虑今天要不要处理。”
**输入**  连续音视频流、事件定义、用户指定的后续任务，以及可选的日历、待办、笔记或订单信息。
**期望输出**  触发事件及时间、完成的工具操作或取得的信息、相关分析与依据、仍需用户决定的事项。
**任务约束**
1. 只在事件发生后执行用户指定的后续任务；同一持续事件默认只执行一次。
2. 从语音或画面提取的责任人、期限、包裹身份等信息不确定时，应标明不确定性。
3. 工具查询得到的信息与音视频中观察到的信息应分别说明。
## 2. 条件触发
### 2.1 语义条件提醒（原 Task 4）
**任务描述**  用户给出一个较抽象的语义条件。模型持续观察音视频流，在满足该条件时主动提醒用户。
**典型指令**
- “再次看到刚才那辆车时提醒我。”
- “当出现适合拍照的场景时告诉我。”
- “当有人开始讨论预算问题时提醒我。”
- “看到类似刚才那个故障现象时提醒我。”
- “当环境变得拥挤或危险时提醒我。”
**任务场景**  智能眼镜、旅行和展馆导览、会议辅助、现场维修、安全监控、个性化陪伴。
**输入**
- 连续音视频流；
- 用户自然语言描述的语义条件；
- 可选的参考目标、参考片段或历史事件。
**期望输出**
- 条件是否满足；
- 触发时间；
- 触发依据；
- 简短提醒。
**任务约束**
1. 模型需要将自然语言条件映射到可观察的音视频证据。
2. “再次出现”需要利用历史记忆进行目标匹配。
3. 复杂语义条件必须有明确的触发窗口和判定标准。
4. 不应因为弱相关线索频繁触发。
5. 用户可以动态修改、暂停或取消条件。
6. 对模糊条件需要保守提醒，并说明判断依据或不确定性。
### 2.2 情境满足后准备信息或提出建议（Agent 任务）
**任务描述**  用户指定一个由语义或多个可观察条件构成的情境，并指定情境成立后要获取的信息、要完成的日常事务或要思考的问题。
**典型指令**
- “当会议开始讨论预算，而我的问题还没被回答时，调出相关资料，帮我想现在该问什么。”
- “当我准备出门且外面下雨时，帮我查路线，并考虑是否调整出发时间。”
**输入**  连续音视频流、用户定义的条件和后续任务，以及可选的笔记、文档、日历、天气或地图信息。
**期望输出**  条件成立的时间与依据、调用工具取得的信息、所提出的建议及其理由。
**任务约束**
1. 必须先判断用户定义的全部必要条件是否在指定窗口内成立，再执行后续任务。
2. 不应把可能即将发生的情境当作已经成立的条件。
3. 对资料缺失或条件含糊的情况，应说明判断的边界。
## 3. 计数触发
### 3.1 实时事件计数（原 Task 7）
**任务描述**  模型持续检测指定事件，并对事件发生次数进行累计，在适当时机主动更新计数或回答当前累计结果。
**典型指令**
- “帮我统计主持人说了多少次‘谢谢’。”
- “数一下红灯亮了多少次。”
- “统计这段视频里有多少次有人摔倒。”
- “每次听到掌声时更新一下总次数。”
**任务场景**  会议和演讲分析、体育比赛统计、行为研究、设备故障记录、训练和康复、内容分析。
**输入**
- 连续音视频流；
- 待计数事件；
- 事件边界和去重规则；
- 可选的输出频率。
**期望输出**
- 当前累计次数；
- 最近一次事件的时间；
- 统计范围；
- 必要时列出各次事件时间点。
**任务约束**
1. 必须区分独立事件和同一事件的持续过程。
2. 需要处理重叠、遮挡、重复发言和背景噪声。
3. 不能使用未来信息修正当前已经输出的结果。
4. 若后续发现误计数，应明确更正，而非静默修改。
5. 用户可以随时询问当前计数或重置计数。
6. 需要明确是按声音、视觉还是音视频联合计数。
### 3.2 条件计数提醒（原 Task 3）
**任务描述**  当指定的音频或视觉事件发生时，模型立即统计当前画面中满足条件的目标数量，并主动报告结果。
**典型指令**
- “每次听到哨声时，告诉我画面里有多少名球员。”
- “看到红灯亮起时，数一下当前有多少辆车。”
- “当有人敲门时，告诉我门外有几个人。”
- “听到警报声时，数一下画面中有多少台设备异常。”
**任务场景**  体育比赛、交通监控、设备巡检、门店和仓库管理、智能家居、现场安全检查。
**输入**
- 连续音视频流；
- 触发事件定义；
- 待计数目标定义；
- 可选的空间范围、属性和去重规则。
**期望输出**
- 触发事件；
- 触发时间；
- 当前目标数量；
- 必要时附带计数依据或目标位置。
**任务约束**
1. 计数必须基于触发时刻的当前场景。
2. 目标进入、离开和短暂遮挡需要正确处理。
3. 同一目标不能因连续帧或重复检测被重复计数。
4. 必须区分“当前数量”和“累计出现次数”。
5. 触发事件未发生时保持沉默。
6. 多个触发事件连续发生时，应分别输出对应结果。
### 3.3 独立对象计数（原 Task 8：语义对象计数）
**任务描述**  模型对连续音视频流中的不同语义对象、类别或事件进行识别和去重，并统计不同对象的数量。
**典型指令**
- “统计今天会议中提到了多少个不同的产品。”
- “数一下画面里出现过多少种不同的鸟。”
- “统计直播中展示了多少种商品。”
- “记录这段讨论里出现过多少个不同的方案。”
**任务场景**  直播带货、展馆和旅行、会议与访谈分析、产品巡检、教学视频、生物和环境观察。
**输入**
- 连续音视频流；
- 目标类别或语义范围；
- 可选的相似目标合并规则。
**期望输出**
- 不同对象的数量；
- 对象名称或类别；
- 首次和最近出现时间；
- 必要时附带对象之间的差异。
**任务约束**
1. 需要区分“出现次数”和“不同对象数量”。
2. 同一对象在不同时间出现时不能重复计算。
3. 需要解决同义词、别名和模糊指代。
4. 视觉和语音提到的对象需要进行跨模态合并。
5. 无法确认是否为同一对象时，应保留候选或标记不确定性。
6. 对象集合可以随用户新指令动态更新。
### 3.4 数量达到阈值后整理或调整计划（Agent 任务）
**任务描述**  用户指定待计数的事件或对象、数量阈值，以及达到阈值后要执行的日常事务或分析。Agent 在数量达到约定阈值时触发，而非每次观察到对象就执行后续任务。
**典型指令**
- “这场会议里分配给我的待办达到 3 项时，帮我整理成清单，并考虑哪些会与现有日程冲突。”
- “购物车里符合购物清单的商品达到 5 件时，更新清单和预计总价，并考虑预算还够买哪些必需品。”
**输入**  连续音视频流、计数对象及去重规则、阈值、后续任务，以及可选的待办、日历、购物清单或预算信息。
**期望输出**  达到阈值的时间、当时的数量与计数依据、完成的工具操作、分析结果。
**任务约束**
1. 明确区分当前数量、累计发生次数与不同对象数量，按用户指定的口径触发。
2. 默认在数量从低于阈值达到或超过阈值时执行一次；数量持续高于阈值时不重复执行。用户可另行指定再次跨越阈值或每增加一定数量时触发。
3. 对重复提及、遮挡后重现或同一目标被多次观察的情况进行去重；发现错误时明确更正。
## 4. 目标触发
### 4.1 目标定位提醒（原 Task 2）
**任务描述**  当指定目标通过视觉或声音出现时，模型主动告知目标是什么，以及目标在当前画面中的位置或声音的来源方向。
**典型指令**
- “看到白猫时告诉我它在画面的哪边。”
- “听到有人呼救时，告诉我声音大概来自哪个方向。”
- “看到出口标志时告诉我它的位置。”
- “听到水滴声时帮我找出可能的来源。”
**任务场景**  视障辅助、智能眼镜、室内导航、设备和零件查找、现场作业、环境声音定位。
**输入**
- 连续第一人称视频；
- 多通道或空间音频；
- 用户指定的目标类别或目标属性。
**期望输出**
- 目标出现提醒；
- 目标类别；
- 目标位置，如左上方、右侧、前方；
- 可选的边界框、方向角或距离估计。
**任务约束**
1. 目标必须真实出现在当前或最近观察窗口中。
2. 位置描述应与触发时刻对齐，不能引用之后才出现的信息。
3. 对视觉目标需要区分目标位置与用户正在注视的位置。
4. 对声音目标需要区分声源方向与声音内容。
5. 目标被遮挡或定位不确定时，应表达不确定性。
6. 不应把语义相关但实际不存在的目标报告出来。
### 4.2 目标监测：离散状态变化监测（原 Task 6）
**任务描述**  用户在任务开始时指定一个主要对象及其某个离散、可观察的状态维度。模型持续监听音视频流，在该状态发生变化的时刻主动报告状态转移。
**模型需要完成**
1. 选择一个适合监测的状态维度。
2. 持续观察或监听该状态。
3. 检测状态从一个值切换到另一个值。
4. 在每次转移发生时主动响应。
5. 明确说明状态变化的方向，例如“从关闭变为打开”。
**典型场景**
- 监测房间灯光从关闭变为打开，再变为关闭；
- 监测设备从正常变为异常；
- 监测车辆从静止变为移动；
- 监测人物从站立变为坐下；
- 监测门从关闭变为打开；
- 监测音乐从停止变为播放；
- 监测不同说话人的交替；
- 监测画面中的人数变化；
- 监测物体是否处于佩戴、拿取或放置状态。
**典型指令**
- “帮我监测这扇门的状态变化，每次变化时提醒我。”
- “持续观察这个设备，状态发生变化时告诉我。”
- “如果这个人从站着变成坐下，或者从坐下变成站起来，提醒我。”
- “帮我注意房间里的灯，开关状态变化时告诉我。”
- “听到说话人发生变化时提醒我。”
**输入**
- 连续视频流、音频流或音视频流；
- 用户在起始时刻给出的监测指令；
- 可选的主体、状态维度和问题时间点；
- 可选的候选主体和属性信息。
**期望输出**  对于每一次状态转移，输出：
- 状态变化发生的时间；
- 变化前的状态；
- 变化后的状态；
- 触发模态；
- 支持该判断的音视频证据；
- 对转移事件的事实性描述。
### 4.3 指定目标出现后完成相关任务（Agent 任务）
**任务描述**  用户指定一个视觉或声音目标，以及目标出现后要完成的日常事务或要考虑的问题。目标可以是画面中的物品、标志，也可以是音频中的指定声音或词语。
**典型指令**
- “听到车厢广播报出我要下的站时，帮我查接下来的步行路线，并考虑走哪个出口。”
- “看到购物清单上的商品时，帮我查有没有优惠，并考虑现在买还是继续比较。”
**输入**  连续音视频流、目标定义、后续任务，以及可选的行程、地图、购物清单或商品信息。
**期望输出**  目标出现时间与识别依据、工具查询结果、与目标相关的建议及不确定性。
**任务约束**
1. 目标必须出现在当前或最近观察窗口中；相似但不符合用户指定属性的目标不得触发。
2. 应区分“当前到站”和“下一站预告”，以及商品名称相同但规格不同的情况。
3. 目标再次出现时是否重新执行任务，由用户设定；默认同一次持续出现只执行一次。
## 要用的工具和推理任务
本节列出上述四个 Agent 任务可能调用的**日常应用与信息服务工具**，以及需要执行的**音视频理解和复杂推理任务**。工具用于触发后的查询、记录或计划管理；语音识别、画面文字理解、目标识别等音视频相关能力归入推理任务，不作为工具调用任务列出。具体使用哪些工具由用户指令和可用接入决定。
### 事件触发 Agent
**工具**：待办创建与查询、日历查询、笔记写入、订单及待收包裹查询与更新。
**推理任务**：理解语音中的交办内容、责任人和期限；从画面理解包裹信息；匹配已有订单；分析时间冲突和处理优先级。
### 条件触发 Agent
**工具**：个人笔记与文档搜索、日历查询、天气查询、地图与路线查询、会议记录草稿工具。
**推理任务**：理解会议话题和已有回答；从音视频判断多个条件是否同时成立；筛选最值得问的问题；综合天气、路程和约定时间给出建议。
### 计数触发 Agent
**工具**：待办查询与更新、日历查询、购物清单查询与更新、预算或记账工具、计算器。
**推理任务**：从语音中区分新任务与重复提及；从画面中识别商品及其数量并去重；判断数量何时达到阈值；分析任务依赖、日程冲突、剩余预算和购买优先级。
### 目标触发 Agent
**工具**：行程查询、地图及站内路线查询、购物清单查询、商品与优惠搜索、计算器。
**推理任务**：理解报站语音并区分当前站与下一站预告；从画面核对商品及规格；比较出口路线、实际价格和替代商品。
