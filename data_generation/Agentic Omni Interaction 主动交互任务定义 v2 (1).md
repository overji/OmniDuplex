# Agentic Omni Interaction 主动交互任务定义 v2

# 一、执行摘要

**核心判断**：将任务体系从 v1 的"四类触发 × 任务"重构为"**12 类认知能力 × 3 种交互模式**"。能力轴迁移自 OmniEval 的 12 类任务（感知 5 类 / 理解 4 类 / 推理 3 类）；交互轴迁移自 Omni\-DuplexEval 的两种实时双工场景——实时描述（Real\-Time Description）与主动提醒（Proactive Reminder），并扩展第三种模式：触发后执行复杂推理或工具调用的 Agent 模式。v1 的四类触发逻辑（事件 / 条件 / 计数 / 目标）不再作为顶层分类，降级为每个任务主动提醒与 Agent 模式的"触发类型"标注。

**依据**：

1. OmniEval 构建了 810 条音视频同步视频、2617 对问答，按 12 类认知任务细粒度分类，其中时间定位（Grounding）342 对，是粒度最细的视频定位任务；

2. Omni\-DuplexEval 提出实时双工评测的两大场景：实时描述（6 个子任务，评测内容一致性与时间敏感性）与主动提醒（3 个子任务，评测事件识别与响应时机），最佳模型总分仅 39\.6%，主动提醒仅 20\.0%，"何时响应"是当前最大短板；

3. v1 文档已沉淀的四个 Agent 任务（事件、条件、计数、目标触发）验证了"触发后执行工具调用与复杂推理"的可行性，本版将其推广到全部 12 类能力。

**约束**：实时性与异步后端强模型调用存在冲突；训练数据中回复时间点早于信息可得时刻会造成数据泄露，二者是数据合成与架构设计必须遵守的边界。

**行动**：按本文定义完成 12 × 3 任务矩阵的路由、合成数据生成与评测标注；具体落地顺序见"六、合成数据 pipeline"。

# 二、设计框架

## （一）双轴任务体系

任务体系由两个正交的轴构成，任何一条任务实例都是"能力 × 模式"的组合：

- **能力轴（12 类）**：迁移自 OmniEval 的 12 类认知任务，按认知深度分为三层——感知（属性感知、时间定位、动作感知、物体感知、情绪识别）、理解（事件理解、文本内容理解、物体计数、动作计数）、推理（空间理解、前瞻推理、因果推理）。

- **交互轴（3 种模式）**：实时描述（RTD，连续、时间对齐地跟踪演化）、主动提醒（PR，检测显著事件并决定何时响应）、Agent 触发（触发后执行复杂推理或工具调用）。

- **触发轴（4 类）**：继承 v1 的事件触发、条件触发、计数触发、目标触发，作为 PR 与 Agent 模式的触发类型标注，不再单独成类。

## （二）三种交互模式

**A · 实时描述（Real\-Time Description）**：用户给出一条关注指令后，模型对连续音视频流持续产出与时间窗口对齐的描述，随画面与声音演化更新输出，要求同时做到"说得对"（内容一致）与"说得及时"（时间敏感）。

**B · 主动提醒（Proactive Reminder）**：用户预先指定一个清晰的事件或条件，模型持续监听流，在事件发生、条件满足或数量达阈值时决定是否响应、何时响应以及说什么；事件不发生必须保持沉默。指令可能出现在时间轴的任意位置，甚至指代过去观察到的目标。

**C · Agent 触发**：在 PR 的事件识别之上叠加执行层。触发后 Agent 可调用日常应用工具（待办、日历、笔记、地图、购物清单等）进行查询与记录，或进行复杂推理（理解交办、分析冲突、归因、预测），或两者兼做；输出需区分"从音视频观察到的"与"从工具查询到的"信息。

# 三、十二类任务定义

以下每个任务给出：能力定义（考查什么，附 OmniEval 原始问题示例）、认知层级与模态依赖、三种交互模式的定义（含典型指令与核心输出）、约束要点。典型指令同时覆盖"用户主动发起"与"系统触发"两种交互形态。

## （一）T1 · 属性感知（Attribute Perception）

**能力定义**：识别并描述人物或物体的属性（颜色、材质、类别、状态等静态特征）。原始问题示例："这个人的衣服是什么颜色？"

**认知层级**：感知｜**模态依赖**：视觉为主，可辅以语音描述。

**A · 实时描述（RTD）**：持续跟踪指定目标的属性及其变化，随时间对齐播报。
典型指令："实时告诉我画面里每个人衣服颜色的变化。"
核心输出：带时间戳的属性描述序列（如"t=5s 穿红裙；t=12s 换成蓝外套"）。

**B · 主动提醒（PR）**（触发类型：条件触发）：目标属性出现、变化或匹配用户指定值时提醒。
典型指令："看到穿红色衣服的人时提醒我。"
期望输出：触发时间、属性证据、简短提醒。

**C · Agent 触发**：属性匹配后执行查询与记录等事务。
典型指令："看到有人穿我上次看中的那件黑衬衫时，提醒我并查一下它的品牌和价格。"
工具：图像/商品检索、笔记；推理：属性匹配、跨时段身份确认。

**约束要点**：属性描述须与触发时刻对齐；相似属性（相近色、相近材质）需明确区分；无法确认时标注不确定性。

## （二）T2 · 时间定位（Grounding）

**能力定义**：将事件定位到具体时刻（moment）或时间段（time span）。原始问题示例："穿红衣服的女孩什么时候开始说话？"

**认知层级**：感知（时序感知）｜**模态依赖**：视音频联合。

**A · 实时描述（RTD）**：为流中事件实时打时间戳并播报，持续报告关键事件的发生时刻。
典型指令："实时告诉我视频里每一次击球的时刻。"
核心输出：事件名称 \+ 发生时间戳的持续序列。

**B · 主动提醒（PR）**（触发类型：事件触发）：用户指定的事件发生时，在发生时刻立即提醒。
典型指令："当解说提到'差距从一开始就拉开'时告诉我时间。"
期望输出：事件时间戳与简短提醒。

**C · Agent 触发**：定位到事件后检索该时段上下文并执行后续。
典型指令："找到她开始说话的时刻，回放并总结她说了什么。"
工具：视频回放/定位、纪要检索；推理：时刻提取、前后上下文关联。

**约束要点**：只能用触发前已观察到的信息；moment 评测允许阈值误差，time span 用交并比（IoU）评测；不能引用未来信息修正输出。

## （三）T3 · 动作感知（Action Perception）

**能力定义**：识别并描述人物正在进行的动作。原始问题示例："画面中的人正在做什么动作？"

**认知层级**：感知｜**模态依赖**：视觉为主，动作伴随音效时可联合。

**A · 实时描述（RTD）**：持续描述动作序列与动作变化。
典型指令："实时描述厨师做菜的动作。"
核心输出：动作名称 \+ 时间窗口的连续描述。

**B · 主动提醒（PR）**（触发类型：事件触发）：指定动作发生时提醒。
典型指令："有人摔倒时提醒我。"
期望输出：触发时间、动作证据、简短提醒。

**C · Agent 触发**：关键或异常动作触发应急、记录或通知。
典型指令："看到老人摔倒时，通知家属并记录时间。"
工具：通讯通知、待办记录；推理：动作边界判定、风险分级。

**约束要点**：区分动作开始、持续与结束；遮挡与快速动作需保守描述；相似动作需给出判别依据。

## （四）T4 · 物体感知（Object Perception）

**能力定义**：识别画面中出现的人物或物体类别。原始问题示例："画面里出现了什么交通工具？"

**认知层级**：感知｜**模态依赖**：视觉。

**A · 实时描述（RTD）**：实时报告画面中新出现的物体及其类别。
典型指令："实时告诉我画面里新出现了什么。"
核心输出：物体类别 \+ 出现时间与位置的播报。

**B · 主动提醒（PR）**（触发类型：目标触发）：指定目标出现时提醒。
典型指令："看到白猫时告诉我它在画面的哪边。"
期望输出：目标出现提醒、类别、位置。

**C · Agent 触发**：目标出现后执行查询、记录或比对。
典型指令："看到购物清单上的商品时，查一下它的价格和优惠。"
工具：购物清单、商品搜索；推理：规格核对、跨模态去重。

**约束要点**：不得报告语义相关但实际不存在的目标；同一类别需区分规格差异；目标被遮挡或不确定时表达不确定性。

## （五）T5 · 情绪识别（Emotion Recognition）

**能力定义**：根据语音韵律、面部表情或情境判断情绪。原始问题示例："说话者听起来是什么情绪？"

**认知层级**：感知｜**模态依赖**：视听联合（语音韵律 \+ 表情 \+ 情境）。

**A · 实时描述（RTD）**：持续描述说话者的情绪状态及其变化。
典型指令："实时告诉我这位演讲者的情绪变化。"
核心输出：情绪标签 \+ 时间点的连续播报。

**B · 主动提醒（PR）**（触发类型：条件触发）：情绪达到异常阈值时提醒。
典型指令："对方听起来生气或难过时提醒我。"
期望输出：触发时间、情绪证据（语气/表情）、简短提醒。

**C · Agent 触发**：负面情绪触发安抚、话术调整或记录。
典型指令："客户听起来不满时，提示我换话术并记录这次沟通。"
工具：话术库、笔记；推理：情绪归因、多模态一致性判断。

**约束要点**：区分语音情绪与内容情绪；多人场景需指明对象；情绪判断为推断而非事实，需标注置信度。

## （六）T6 · 事件理解（Event Understanding）

**能力定义**：理解视频中发生的事件及其关系（时序、因果、主次）。原始问题示例："这个片段主要发生了什么？"

**认知层级**：理解｜**模态依赖**：视听联合。

**A · 实时描述（RTD）**：实时解说事件进展与事件间关系。
典型指令："实时解说球场上发生的重要事件。"
核心输出：事件内容、相关人物物体及其关系的连续解说。

**B · 主动提醒（PR）**（触发类型：事件触发）：重要事件发生时提醒。
典型指令："进球时提醒我。"
期望输出：触发时间、事件类型、简短提醒。

**C · Agent 触发**：事件发生后整理纪要、更新日程或通知。
典型指令："会上有人给我安排任务时，记到待办里并考虑什么时候做。"
工具：待办、日历、笔记；推理：交办内容与责任人提取、期限识别、时间冲突分析。

**约束要点**：只描述当前或已发生的事件，不预测未发生的事实；区分事实描述与推测性解释；连续描述保持上下文一致。

## （七）T7 · 文本内容理解（Text\-Rich Understanding）

**能力定义**：读取并理解视频内的文字信息（字幕、标志、屏幕文本、告示）。原始问题示例："屏幕上的告示写了什么？"

**认知层级**：理解｜**模态依赖**：视觉（动态文本 OCR）\+ 语境。

**A · 实时描述（RTD）**：实时读取并播报动态变化的文本。
典型指令："实时读出电梯楼层号的变化。"
核心输出：文本内容 \+ 视觉切换时刻的同步播报。

**B · 主动提醒（PR）**（触发类型：条件触发）：指定文本内容出现时提醒。
典型指令："看到'出口'标志时告诉我它的位置。"
期望输出：触发时间、文本内容、位置。

**C · Agent 触发**：读到关键文本后检索信息或执行任务。
典型指令："车厢广播报到我该下的站时，查接下来的步行路线。"
工具：地图/行程、搜索；推理：当前站与下一站预告区分、规格与地点匹配。

**约束要点**：文本出现与播报须同步，避免滞后；区分屏幕文本与场景内标牌；文本残缺时标注不确定性。

## （八）T8 · 物体计数（Object Counting）

**能力定义**：统计画面中的物体数量。原始问题示例："桌上出现了几个杯子？"

**认知层级**：理解｜**模态依赖**：视觉。

**A · 实时描述（RTD）**：实时更新画面中的目标数量，跟踪进入、离开与遮挡。
典型指令："实时告诉我画面里有多少人。"
核心输出：当前数量 \+ 数量变化事件（有人进入/离开）的持续播报。

**B · 主动提醒（PR）**（触发类型：计数触发）：数量达到阈值或发生指定变化时提醒。
典型指令："画面里人数超过 10 时提醒我。"
期望输出：触发时间、当前数量、计数依据。

**C · Agent 触发**：数量达到阈值后整理、补货或通知。
典型指令："购物车里符合清单的商品达到 5 件时，更新清单和预计总价。"
工具：购物清单、预算、计算器；推理：跨帧去重、阈值判断、购买优先级。

**约束要点**：区分"当前数量"与"累计出现次数"；同一目标因遮挡重现不得重复计数；计数基于触发时刻的当前场景。

## （九）T9 · 动作计数（Action Counting）

**能力定义**：统计某个动作发生的次数。原始问题示例："这个人拍了几次手？"

**认知层级**：理解｜**模态依赖**：视觉为主，可联合声音事件（掌声、哨声）。

**A · 实时描述（RTD）**：实时累计动作次数并播报当前累计值。
典型指令："实时统计主持人说了多少次'谢谢'。"
核心输出：累计次数 \+ 最近一次事件时间的持续更新。

**B · 主动提醒（PR）**（触发类型：计数触发）：达到指定次数时提醒。
典型指令："掌声达到 3 次时提醒我。"
期望输出：触发时间、累计次数。

**C · Agent 触发**：次数达到阈值后统计、分析或生成报告。
典型指令："画面里有人摔倒的次数达到 2 次时，生成一份安全观察报告。"
工具：统计工具、报告模板；推理：独立事件判定（区分一次动作的持续与多次动作）、趋势分析。

**约束要点**：必须区分独立事件与同一事件的持续过程；发现误计数须明确更正而非静默修改；明确按视觉、听觉还是联合口径计数。

## （十）T10 · 空间理解（Spatial Understanding）

**能力定义**：判断物体之间的位置或空间关系。原始问题示例："杯子在书的左边还是右边？"

**认知层级**：推理｜**模态依赖**：视觉。

**A · 实时描述（RTD）**：实时报告目标位置与相对关系的变化。
典型指令："实时告诉我车离我多远、往哪个方向开。"
核心输出：相对位置/距离 \+ 移动方向的连续播报。

**B · 主动提醒（PR）**（触发类型：条件触发）：空间关系成立或目标到达指定位置时提醒。
典型指令："球滚到桌边时提醒我。"
期望输出：触发时间、位置证据、简短提醒。

**C · Agent 触发**：位置条件满足后导航、提醒或记录。
典型指令："目标走到门口时提醒我开门。"
工具：地图/导航；推理：相对位置判定、距离估计。

**约束要点**：位置描述须与触发时刻对齐；区分目标位置与用户注视位置；遮挡或深度不确定时表达不确定性。

## （十一）T11 · 前瞻推理（Prospective Reasoning）

**能力定义**：根据当前情境推断接下来最可能发生什么。原始问题示例："球滚向桌边后，接下来最可能发生什么？"

**认知层级**：推理｜**模态依赖**：视听联合。

**A · 实时描述（RTD）**：随新证据持续更新对后续发展的预测。
典型指令："实时预测这辆车接下来会怎么开。"
核心输出：预测 \+ 置信度 \+ 更新依据的持续播报。

**B · 主动提醒（PR）**（触发类型：条件触发）：检测到高风险前兆时预警。
典型指令："球快滚下桌时提醒我接住它。"
期望输出：预警时间、前兆证据、预测结论。

**C · Agent 触发**：预测到风险后规划应对或通知。
典型指令："预测到我会迟到时，帮我改签并通知对方。"
工具：日历、出行、天气；推理：概率估计、预案匹配。

**约束要点**：预测必须标注为推测而非事实；随证据更新预测时说明变化依据；不得把可能即将发生当作已经成立。

## （十二）T12 · 因果推理（Causal Reasoning）

**能力定义**：解释事件为什么发生。原始问题示例："为什么玻璃杯掉到了地上？"

**认知层级**：推理｜**模态依赖**：视听联合。

**A · 实时描述（RTD）**：在描述事件的同时同步给出原因解释。
典型指令："实时解释设备每次告警的原因。"
核心输出：事件 \+ 原因解释 \+ 事实与推测的区分。

**B · 主动提醒（PR）**（触发类型：事件触发）：异常事件发生时触发原因分析提醒。
典型指令："设备报警时告诉我可能的原因。"
期望输出：触发时间、事件描述、候选原因及依据。

**C · Agent 触发**：事件发生后深度归因、检索信息并给出建议。
典型指令："机器停机时，查一下历史故障记录并给出排查建议。"
工具：知识库、历史记录；推理：多因归因、证据排序。

**约束要点**：区分观察到的因果与推断的因果；多因并存时列出可能原因与优先级；推理边界需说明。

# 五、评测框架

## （一）三层评测维度

Benchmark 不应只评价"回答对不对"，还应同时评价三个维度：

1. **时机决策**：是否在正确的时间交互（PR 与 Agent 模式的核心指标，回答"何时响应"）；

2. **内容质量**：交互内容是否准确、相关、完整（RTD 的核心指标，回答"说什么"）；

3. **类型决策**：选择沉默、即时回复还是后台托管（Agent 模式特有，回答"以何种方式响应"）。

## （二）实时描述（RTD）评测

采用内容一致性与时间敏感性二维联合评分（LLM\-as\-a\-Judge）：

- **内容一致性（Content Consistency）**：整体语义对齐，扣分制惩罚事实错误、幻觉与遗漏；

- **时间敏感性（Temporal Sensitivity）**：句级时间对齐，流程为"语义相关性过滤（剔除客套语等非实质句）→ 多窗口采样（容忍约 2 秒感知\-生成延迟）→ 多模态上下文抽取（2 FPS 抽帧 \+ 对应音频）→ 打分（取候选窗口最高分）"；

- 总评 = 0\.5 × 内容一致性 \+ 0\.5 × 时间敏感性；无效句占比会衰减时间分。

## （三）主动提醒（PR）评测

- 以事件时间戳为锚，在事件后固定窗口（如 10 秒）内提取模型响应；

- 同时评估事件识别是否正确、响应内容与用户指令是否一致；

- 目标事件多次发生时，须对所有发生均正确响应才算成功；事件不发生时应保持沉默。

## （四）Grounding 评测

- **时刻型（moment）**：预测时刻与真值之差不超过阈值 τ（τ 由帧率与最大帧数决定），即判定正确；

- **时间段型（time span）**：预测区间与真值区间的交并比（IoU）不低于 0\.5，即判定正确。

## （五）三类决策的联合评估

对 Agent 模式，先判定"是否触发、以何种类型触发"，再评估触发后工具调用的正确性与推理结论的质量；工具查询信息与音视频观察信息分开评分，避免以工具信息掩盖感知错误。

# 六、合成数据 pipeline

在 v1 的 pipeline 基础上按新模式扩展，四步流程如下：

1. **Caption（事件标注）**：标注视频中的音频事件与视频事件，并将事件与画面中物体组合，形成带时间戳的事件\-物体\-属性三元组；

2. **Router（任务路由）**：按 12 类能力 × 3 种交互模式选择任务实例；同一视频片段可产出多条不同能力\-模式组合的样本（如"动作感知 \+ RTD"与"动作感知 \+ PR"共用同一事件标注）；

3. **合成数据**：按模式生成训练样本——RTD 生成连续、时间对齐的描述；PR 生成事件定义 \+ 时间戳 \+ 响应指令（指令可出现在时间轴任意位置）；Agent 生成触发条件 \+ 工具调用记录 \+ 推理过程；

4. **数据筛选**：每条 response 必须能由先前视频内容推导（因果时间一致性）；回复时间点不得早于信息可得时刻，防止数据泄露；同时过滤可被所有模型答对的过易样本。
