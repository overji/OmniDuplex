# 首答与后续回复：历史普通 CE SFT 轨迹复核

对象：旧版 5k 数据普通 CE SFT 的 final 模型与 MiniCPM-o-4.5 基座。**不是当前正在训练的筛选后全量模型**。评测为 realtime，沿用原始输出和窗口内一对一 onset 匹配，没有恢复或改写模型输出，没有新推理。

采用筛选后 1,998 QA，并以 QA SHA256 将历史 2,110 索引转换至旧公开 2,107 索引。首次窗口按时间排序。命中只代表时间，不代表内容正确。

| 任务 | 模型 | 首次窗口 Recall | 后续窗口 Recall |
| --- | --- | ---: | ---: |
| all | base | 25.23% (504/1998) | 22.49% (546/2428) |
| all | sft | 41.54% (830/1998) | 19.60% (476/2428) |
| rtd | base | 23.75% (147/619) | 21.60% (408/1889) |
| rtd | sft | 33.28% (206/619) | 17.89% (338/1889) |
| pr | base | 40.03% (265/662) | 26.34% (133/505) |
| pr | sft | 45.77% (303/662) | 26.53% (134/505) |
| agent | base | 12.83% (92/717) | 14.71% (5/34) |
| agent | sft | 44.77% (321/717) | 11.76% (4/34) |

控制首答是否命中：限定两模型都命中首个窗口的相同 154 条多回复 QA，共 313 个后续窗口。基座后续召回 39.94% (125/313)；SFT 35.14% (110/313)。这说明差异不完全来自首答成功样本集合变化，但仍不是首答造成失败的因果证明。

## 漏答不等于一直沉默

- base：命中首答且有后续参考窗口的 QA 为 262 条；其中 122 条后续窗口全部漏掉。后者中 54 条首答后没有新的 event，另 68 条仍有 event，但没有命中后续窗口。这个条件集合随模型变化，不能直接作为公平比较。
- sft：命中首答且有后续参考窗口的 QA 为 353 条；其中 194 条后续窗口全部漏掉。后者中 161 条首答后没有新的 event，另 33 条仍有 event，但没有命中后续窗口。这个条件集合随模型变化，不能直接作为公平比较。

## 一个具体例子

旧索引 164，筛选后索引 158；RTD；视频 `2ad7f905-2a3c-5590-ba71-02db9f003732.mp4`。

问题：Keep me updated on what the musicians in the video are doing throughout their performance.

- 首个窗口 00:01–00:07：吉他手唱歌并弹琴，另一人持小号。
- 后续窗口 00:11–00:20：小号手开始独奏，吉他手停止唱歌、继续伴奏。
- 基座在 2 s、12 s 各开启一次回复，命中两个窗口。
- SFT 仅在 1 s 开启一次回复，后面没有新的回复 event，漏掉第二个窗口。
- 两者均以 complete 状态完成，观测视频时长：base 60.005 s，SFT 60.005 s。

原文与全部 31 条“双方首答命中、基座后续有命中而 SFT 全漏”的 RTD/PR 反例见同名 JSON。计数依据新回复的 onset event；“无新 event”不等价于逐 token 证明一直沉默，也不能排除单次回复的续说。

## 结论边界

历史普通 CE SFT 存在后续窗口召回退化，主要集中在 RTD；PR 的总体后续召回没有下降。不能概括为所有任务都是首答后失败，更不能将该历史结论直接套到当前训练中的模型。当前的 later-onset loss 只能提示风险，需要当前 checkpoint 的自主生成评测才能确认。
